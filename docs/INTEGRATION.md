# Native PS5 integration plan

isShelf has an offline browser design preview, a native C++ UI running on PC and a private PS5 test app. Its original [read-only discovery adapter](DISCOVERY.md) has scanned the owner's existing libraries from PC and inside the console app without moving their games. The owner confirmed UI-15 closes Shelf and opens PS5SX2 directly on the TV. Other launch routes remain pending console acceptance.

The [first native prototype](PROTOTYPE-PLAN.md) is the main goal. Its C++17 renderer, catalogue/browsing model, navigation, recoverable settings and bounded discovery pass host checks. The owner has confirmed the grid, settings access, compact Circle hint and three-second hold-to-close on firmware 12.20. Console-local discovery records 92 games and 55 routes without a connection failure. The selection artwork is visible; opening still shows black before the grid. Further emulator layouts and launch routes need console validation. A public installable package remains pending.

The native app adapts [Jewel Case](https://github.com/SkaRift/JewelCase)'s platform integration; its discovery and launch architecture remains a reference, with [Estante](https://github.com/kauansilvalopes/estante) as a reference for native PS5/PS4 titles. Shelf keeps its original console-first Grid and Swipe UI. Both reference projects publish GPL source; see [credits](../THIRD_PARTY.md).

An installed emulator or RetroArch core is a route to try, not a promise that every game will work. Jewel Case's [v1.1.1 notes](https://github.com/SkaRift/JewelCase/releases/tag/v1.1.1) say PSXS5 and PS5SX2 open their own menus rather than a selected game. PS5SX3 needs its own adapter. [RetroArch v4's game-request interface](https://github.com/mihawk-99/PS5_RetroArch/blob/v4.0.0-beta-4/src/ps5_game.h) offers a specific game launch route, but the end-to-end integration still needs console testing. The Shelf should read existing emulator folders and deduplicate titles instead of moving or copying game libraries into a new layout.

The native build also needs controller input, title and game inventory, per-system preferred emulator settings, graceful handling when a loader is unavailable, save-preserving upgrades, and tests on the target firmware. Switch 2 remains a hardware reference with no verified PS5 emulator route. No PS5 package is published from this repository yet.

The original launch protocol and cooperative handoff policy have host tests in `native/include/shelf/launch_protocol.hpp` and `native/tests/launch_tests.cpp`. They reject stale, malformed and injected requests, restrict emulator menus to known app IDs, and preserve filenames as individual arguments. The RetroArch route follows its [external forwarder contract](https://github.com/mihawk-99/PS5_RetroArch/blob/v4.0.0-beta-4/src/frontend_mode_ps5.cpp): `--rom <path> --core <id> --exit-after-game`, without an internal frontend-mode switch. The helper waits for Shelf to close itself, refuses an unrelated or unknown running app, and makes one cold launch. An accepted but unobserved target stays unconfirmed and receives no follow-up.

`npm run build:ps5-launch-helper` cross-compiles the original platform helper in `native/ps5/helper/`, using the ordinary SDK payload format rather than the app's native SELF format. The app embeds those exact verified bytes and sends them only to the existing console-local ELF loader on port 9021 when a launch is selected. No extra autoload entry or persistent server is needed. It consumes one fresh owned request, writes a request-bound status only in Shelf's data folder, and has no process-kill or arbitrary emulator-file-write command. Review its SDK-linked source/license materials and assemble matching source/relinking artifacts before a public binary release.

The handoff requires two phases: the helper acknowledges readiness, then Shelf explicitly commits the matching request before closing. A pending or cancelled request cannot authorize a launch after the app disappears. Status replies bind the request ID and timestamp, and stale, duplicate or malformed replies are rejected. The helper also binds the original Shelf app instance and refuses a different foreground application. Host tests cover cancellation before commitment and during closure. Nine loopback transport fixtures cover success, cancellation, late replies, a missing loader, timeout, a mismatched request, a busy handoff, stale requests and invalid input. They send a synthetic packet and never execute a helper.

The private UI offers an emulator-menu test, selected-core RetroArch direct-game plans, and registered native-title plans. Standalone emulators open their own shelf unless a separate direct-game contract is verified. The PC preview remains disconnected from launching. UI-14 tested the delayed running-title request documented in Swordpdf's [pinned disc-launch helper](https://github.com/Swordpdf/PS5SX2/blob/bea3c2e8420934aad24d5665eb75b8a6e462d452/ps5/disclaunch/disc_launch.c). On this firmware it still left the home screen in front. The retained kernel snapshot shows the duplicate launch aborted with `0x8094000c`; that return is not foreground acceptance. Shelf does not use `SetAppFocus`, whose controller-focus issues are also documented by that source.

UI-15 instead makes one `sceSystemServiceLaunchApp` request, following the public [PS5 Payload Web Server title-launch interface](https://github.com/ps5-payload-dev/websrv/blob/7748df9d2a43822a5ebfda149f43d4f2696d640b/src/ps5/sys.c). Its context has an explicit 32-byte size and retains `SkipSystemUpdate`. It then only observes the same target instance and the shell's read-only focus flag, whose interface is documented by [ShadowMountPlus](https://github.com/drakmor/ShadowMountPlus/blob/9ffcbe131575153266e951ab473bb6fd100d8c80/src/sm_shellcore_flags.c). The observer uses OR polling without clear/set flags, closes its handle, and stops on unknown focus, another app, a changed user, cancellation or expiry. There is no second launch or focus-changing call. `foreground-observed` means the shell flag matches the target, not proof of TV output. A background or unknown result remains unconfirmed. The owner has separately confirmed the visible PS5SX2 menu handoff; other routes still need physical tests.

Default builds use a restricted source-rebuilt CRT, excluding SDK credential/syscall patching and the unused custom shared-object loader. Its original no-op/refusal hooks are checked in the final helper. On the owner's console the restricted runtime refuses the running-app query with `0x8094000f` before commitment. The owner explicitly approved the alternative standard SDK runtime for Shelf's tests. Build it with `node tools/build-ps5.js build_ps5.py --standard-helper-runtime`. The pinned, unmodified SDK startup adjusts the helper process's capabilities and syscall bounds in RAM. Receipts identify `standard-sdk` and `permissionChanges: true`. This approval does not cover firmware, network settings, persistent OS changes or unrelated payloads. Preserve the build flag when reproducing this variant. Hardware acceptance and the matching full source/license/relinking package remain required before a public binary download.
