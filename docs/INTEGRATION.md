# Native PS5 integration plan

Console Shelf has an offline browser design preview, a native C++ UI running on PC and a cross-compiled PS5 development executable. Its original [read-only discovery adapter](DISCOVERY.md) has scanned a real PS5 library from PC and inside the console app. A private launch candidate now connects the UI to Shelf's cooperative helper; no console launch has been verified yet.

The [first native prototype](PROTOTYPE-PLAN.md) is the main goal. Its C++17 renderer, catalogue/browsing model, navigation, recoverable settings and bounded discovery pass host checks. The owner has confirmed the grid and basic input on firmware 12.20, but requested simpler controls and more fluid navigation. Console-local configured discovery now completes: the sixth build's journal records 92 games and 55 routes without a connection failure. The revised controls, loading/closing transitions, further dedicated-emulator layouts and launch adapters still need validation. A public installable package remains pending.

The native app adapts [Jewel Case](https://github.com/SkaRift/JewelCase)'s platform integration; its discovery and launch architecture remains a reference, with [Estante](https://github.com/kauansilvalopes/estante) as a reference for native PS5/PS4 titles. Shelf keeps its original console-first Grid and Swipe UI. Both reference projects publish GPL source; see [credits](../THIRD_PARTY.md).

An installed emulator or RetroArch core is a route to try, not a promise that every game will work. Jewel Case's [v1.1.1 notes](https://github.com/SkaRift/JewelCase/releases/tag/v1.1.1) say PSXS5 and PS5SX2 open their own menus rather than a selected game. PS5SX3 needs its own adapter. [RetroArch v4's game-request interface](https://github.com/mihawk-99/PS5_RetroArch/blob/v4.0.0-beta-4/src/ps5_game.h) offers a specific game launch route, but the end-to-end integration still needs console testing. The Shelf should read existing emulator folders and deduplicate titles instead of moving or copying game libraries into a new layout.

The native build also needs controller input, title and game inventory, per-system preferred emulator settings, graceful handling when a loader is unavailable, save-preserving upgrades, and tests on the target firmware. Switch 2 remains a hardware reference with no verified PS5 emulator route. No PS5 package is published from this repository yet.

The original launch protocol and cooperative handoff policy now have host tests in `native/include/shelf/launch_protocol.hpp` and `native/tests/launch_tests.cpp`. They reject stale, malformed and injected requests, restrict emulator menus to known app IDs, and preserve filenames as individual arguments. The RetroArch route follows its [external forwarder contract](https://github.com/mihawk-99/PS5_RetroArch/blob/v4.0.0-beta-4/src/frontend_mode_ps5.cpp): `--rom <path> --core <id> --exit-after-game`, without an internal frontend-mode switch. The helper policy waits for Shelf to close itself, refuses an unrelated or unknown foreground app, and makes at most one launch attempt. An accepted but unobserved request stays unconfirmed.

`npm run build:ps5-launch-helper` cross-compiles the original platform helper in `native/ps5/helper/`, using the ordinary SDK payload format rather than the app's native SELF format. The app embeds those exact verified bytes and sends them only to the existing console-local ELF loader on port 9021. It consumes one fresh owned request, writes a request-bound status only in Shelf's data folder, and has no process-kill or arbitrary emulator-file-write command. The new helper has not been executed on the console. Review its SDK-linked source/license materials and assemble matching source/relinking artifacts before a public binary release.

The handoff requires two phases: the helper acknowledges readiness, then Shelf explicitly commits the matching request before closing. A pending or cancelled request cannot authorize a launch after the app disappears. Status replies bind the request ID and timestamp, and stale, duplicate or malformed replies are rejected. The helper also binds the original Shelf app instance and refuses a different foreground application. Host tests cover cancellation before commitment and during closure. Nine loopback transport fixtures cover success, cancellation, late replies, a missing loader, timeout, a mismatched request, a busy handoff, stale requests and invalid input. They send a synthetic packet and never execute a helper.

The private UI offers an emulator-menu test, selected-core RetroArch direct-game plans, and registered native-title plans. Standalone emulators open their own shelf unless a separate direct-game contract is verified. The PC preview remains disconnected from launching. The first PS2 test confirmed Shelf closes and PS5SX2 starts, but the owner found the PS5 home screen remains in front. A running title is therefore only partial acceptance, not a verified foreground handoff. The revised policy observes a full idle second after Shelf disappears, following the reference launcher's settling interval, and cancels if another app appears. These routes remain experimental until matching console tests pass.

Review of the standard SDK CRT identified automatic per-process credential and syscall-bound changes. The next helper rebuilds that CRT from verified complete source, excludes `patch.c` and the unused custom shared-object loader, and provides three original no-op/refusal hooks in `native/ps5/helper/runtime_limits.c`. It keeps the permissions supplied by the existing loader. Its verifier checks the hooks' actual machine code and rejects linked credential-changing or kernel-write functions. The earlier private PS2 test used the SDK's ordinary startup; the replacement runtime ran but refused at the active-app guard before commitment. Its zero status code does not identify the API failure. The next diagnostic records the running-app query and title-query result in an owned log, without changing permissions or making an extra launch attempt.

The UI-12 diagnostic records successful service initialisation and foreground-user queries, followed by `0x8094000f` from the running-app query. Shelf cancels before commitment. Default builds remain restricted. The build-only option `node tools/build-ps5.js build_ps5.py --standard-helper-runtime` stages the pinned SDK runtime used by the earlier working test. Its automatic startup changes runtime process capabilities and syscall bounds; this mode requires the owner's approval before console use. Receipts label the mode and permission changes. The active-app guard and one-attempt launch policy stay in place.
