# Native PS5 integration plan

Console Shelf has an offline browser design preview, a native C++ UI running on PC and a cross-compiled PS5 development executable. Its original [read-only discovery adapter](DISCOVERY.md) has now scanned a real PS5 library from PC. It does not launch an emulator yet.

The [first native prototype](PROTOTYPE-PLAN.md) is the main goal. Its C++17 renderer, catalogue/browsing model, navigation, recoverable settings and bounded discovery pass host checks. The owner has confirmed the grid and basic input on firmware 12.20, but requested simpler controls and more fluid navigation. Console-local configured discovery now completes: the sixth build's journal records 92 games and 55 routes without a connection failure. The revised controls, loading/closing transitions, further dedicated-emulator layouts and launch adapters still need validation. A public installable package remains pending.

The native app adapts [Jewel Case](https://github.com/SkaRift/JewelCase)'s platform integration; its discovery and launch architecture remains a reference, with [Estante](https://github.com/kauansilvalopes/estante) as a reference for native PS5/PS4 titles. Shelf keeps its original console-first Grid and Swipe UI. Both reference projects publish GPL source; see [credits](../THIRD_PARTY.md).

An installed emulator or RetroArch core is a route to try, not a promise that every game will work. Jewel Case's [v1.1.1 notes](https://github.com/SkaRift/JewelCase/releases/tag/v1.1.1) say PSXS5 and PS5SX2 open their own menus rather than a selected game. PS5SX3 needs its own adapter. [RetroArch v4's game-request interface](https://github.com/mihawk-99/PS5_RetroArch/blob/v4.0.0-beta-4/src/ps5_game.h) offers a specific game launch route, but the end-to-end integration still needs console testing. The Shelf should read existing emulator folders and deduplicate titles instead of moving or copying game libraries into a new layout.

The native build also needs controller input, title and game inventory, per-system preferred emulator settings, graceful handling when a loader is unavailable, save-preserving upgrades, and tests on the target firmware. Switch 2 remains a hardware reference with no verified PS5 emulator route. No PS5 package is published from this repository yet.

The original launch protocol and cooperative handoff policy now have host tests in `native/include/shelf/launch_protocol.hpp` and `native/tests/launch_tests.cpp`. They reject stale, malformed and injected requests, restrict emulator menus to known app IDs, and preserve filenames as individual arguments. The RetroArch route follows its [external forwarder contract](https://github.com/mihawk-99/PS5_RetroArch/blob/v4.0.0-beta-4/src/frontend_mode_ps5.cpp): `--rom <path> --core <id> --exit-after-game`, without an internal frontend-mode switch. The helper policy waits for Shelf to close itself, refuses an unrelated or unknown foreground app, and makes at most one launch attempt. An accepted but unobserved request stays unconfirmed.

`npm run build:ps5-launch-helper` now cross-compiles the original platform helper in `native/ps5/helper/`, using the ordinary SDK payload format rather than the app's native SELF format. It consumes one fresh owned request, writes a request-bound status only in Shelf's data folder, and has no process-kill or arbitrary emulator-file-write command. It has not been deployed or executed. Console transport and UI integration remain absent; these tests/builds do not establish any launch capability. Review the helper's SDK-linked source/license materials and assemble matching source/relinking artifacts before a public binary release.

The handoff now requires two phases: the helper acknowledges readiness, then Shelf explicitly commits the matching request before closing. A pending or cancelled request cannot authorize a launch after the app disappears. Status replies bind the request ID and timestamp, and stale, duplicate or malformed replies are rejected. The host tests cover cancellation before commitment and during closure. This policy is preparation for the transport integration, not an installed launch feature.
